# v10.3 LLM 백엔드 이관 계획

- 기준: `pc_sampling_fuzzer_v10.2.py` (10.2.0)
- 상태: **P0·P1·P2 구현 완료, P3 계측만**. D1~D7 합의 완료
- **구현 완료 ≠ 실서버 검증 완료.** §6 착수 전 통과 조건은 DGX vLLM·실기가 있어야
  확인되며 아직 하나도 통과하지 않았다. 진행 상태는 `pc_sampling_fuzzer_v10.3.md` 가 정본
- 리뷰용 페이지: 같은 내용의 웹 버전이 별도로 있다(아티팩트)

사내 LLM 서비스 의존을 끊고 DGX Spark 의 로컬 vLLM 으로 옮긴다. 검색(RAG)은 사내
인덱스를 재현하는 대신, 사내에서 추출한 JSONL 로 로컬 인덱스를 세운다.

## 1. 목적

지금 구조는 **오프라인 퍼징 PC → Samba 드롭박스 → 온라인 LLM PC** 2노드다. 온라인 PC 가
더 이상 연결돼 있지 않아 LLM 경로가 끊겼고, 그 이전에도 이 경로는 반복해서 캠페인을
멈춰 세웠다.

2026-09-11 에 확인된 마지막 장애가 이 구조의 성격을 보여준다. 프롬프트가 커지자 사내
RAG 의 임베딩 단계가 입력을 거부했는데, 응답 처리 코드가 오류 본문을 버려서
`KeyError: 'hits'` 한 줄만 남았다. 원인 확정까지 서비스 세 버전을 롤백해 가며 바깥에서
소거해야 했다.

```
error_code   QUERY_TOKEN_LIMIT_EXCEEDED
query_tokens 8,498        ← system 1,760자 + user 17,710자
max_tokens   8,192        ← bge-m3 임베딩 상한
model        bge-m3
```

목표는 셋이고 중요도 순이다.

| | 목표 | 내용 |
|---|---|---|
| **G1** | 단일 장비 자립 | 퍼징 PC 와 DGX Spark 만으로 LLM 경로가 완결된다. Samba 공유·드롭박스 폴링·온라인 PC 브리지 서비스가 없어진다. vLLM 서버 자체는 운영 대상으로 남는다 |
| **G2** | 응답 형식 오류 감소 | `response_format: json_schema` 로 구조화 출력을 강제해 형식 오류를 크게 줄인다. 잘림·스키마 거부·통신 실패·의미상 무효는 남으므로 **실패 검증은 유지한다** |
| **G3** | 내부 스펙 투입 경로 | 사내 PDF→JSONL 로 뽑은 문서를 명령 한 줄로 인덱스에 추가할 수 있게 한다 |

### 두 상한은 다른 단계의 제약이다

8,192 는 **임베딩** 입력(bge-m3)의 상한이고, 1,000,000 은 **생성** 모델의 컨텍스트다.
bge-m3 를 계속 쓰는 한 임베딩 쪽 8,192 는 그대로 남는다.

```
짧은 검색 쿼리          →  bge-m3 (≤8,192)  →  관련 문서 top-k
system + user + 문서    →  Nemotron (≤1M)   →  응답 생성
```

질의와 생성 입력의 분리는 부수 효과가 아니라 **P2 의 요구사항**이다. 생성 상한이 커진 덕은
따로 있다 — v10.2 가 붙이는 근거 블록(실행 이력 최대 25,542자, setup 템플릿 최대
25,053자)이 *생성* 입력을 압박하던 문제는 사라진다.

## 2. 현황과 새 자산

### 바꾸지 않는 것

퍼저는 LLM 백엔드를 설정으로 동적 로드한다.

```json
"module_path": "rag.rag_bridge_client",
"func_name":   "generate_rag_response",
"pass_system_prompt": false
```

NVMe 발송 경로, 제품별 샘플러, 커버리지 모델, corpus·변이 엔진은 범위 밖이다.
`llm_learning.py` / `riscv_cov.py` / `nvme_seeds.py` 는 버전 접미사가 없는 공유 자산이라
복사하지 않는다.

### 새로 쓰는 것

| 자산 | 값 | 비고 |
|---|---|---|
| 추론 서버 | `http://192.168.10.1:8000/v1` | 테스트 PC 와 **직결**(PC 는 192.168.10.2). IP 가 바뀔 수 있어 설정값으로 받는다. 초안의 192.168.137.238 은 office PC 쪽 경로라 쓰면 Errno 113 이 난다 |
| 모델 | `nemotron-3-super` | OpenAI 호환 API |
| 인증 | 없음 | 임의 문자열 |
| 생성 컨텍스트 | 1,000,000 | 임베딩 상한과는 별개 단계 |
| 임베딩 | `bge-m3` | 입력 상한 8,192 — **질의와 문서 청크 양쪽**에 적용 |
| 문서 | NVMe Base 2.3 / NVM Command Set 1.2 / MI 2.1 / PCIe 5.0 / TCG Core 2.01 | 약 3,000쪽, 전부 로컬 보유 |

JSONL 은 사내 PDF→JSONL 시스템이 만든다. 내부 스펙도 같은 형식으로 나온다.

```json
{"doc_id": string, "title": string, "content": string, "permission_groups": [string]}
```

**텍스트 추출 품질이라는 가장 어려운 단계를 사내 시스템이 해결해 준다.** 스펙 PDF 를 직접
파싱하면 상태코드 표·CDW 비트 레이아웃처럼 정확히 이 퍼저에 필요한 내용이 깨진다.

## 3. 단계

네 단계는 순서가 있고 앞 단계가 동작한 뒤 시작한다. **RAG 의 기여를 측정하기 위해서다** —
한 번에 바꾸면 개선이 모델 때문인지 검색 때문인지 가릴 수 없다.

### P0 — v10.3 생성 (반나절)

- **산출물**: `pc_sampling_fuzzer_v10.3.py`(v10.2 복사 + `FUZZER_VERSION="10.3.0"` +
  버전 요약 한 줄), `docs/pc_sampling_fuzzer_v10.3.md`
- **검증**: 현재 **92개** 시험 통과, `--help` 동작
- **AST 기준**: **재생성하지 않는다.** 시험 *대상*만 v10.3 으로 바꾸고, 비교 *기준*은
  검증된 v10.2 장치 경로(`tests/fixtures/v10_2_device_ast.json`)로 고정한다. 후보 코드에서
  해시를 다시 뽑으면 의도치 않은 변경까지 승인하게 된다
- **되돌리기**: v10.2 실행 파일이 그대로 남는다

### P1 — vLLM 생성 교체, 검색 없음 (1일)

`rag/vllm_client.py` 를 만들고 설정을 바꾼다. 브리지·드롭박스·온라인 서비스가 빠진다.

```
generate_rag_response(system, user, meta) → dict
  meta   = {task, req_id, rag_query, config, …}    ← 입력. 백엔드는 수정하지 않는다
  return = {"raw": "JSON 문자열",
            "diagnostics": {finish_reason, usage, retrieval, …}}

  └ POST {base_url}/chat/completions
      model = nemotron-3-super
      messages = [system, user]                    ← pass_system_prompt: true
      response_format = {type: "json_schema", …}   ← task 별 스키마
```

**호출 계약**

- **입력** — `meta` 로 task·req_id·검색 질의·**실제 로딩된 설정**을 넘긴다. 최초 호출과
  교정 호출에 동일하게 적용한다.
- **반환** — 기존 백엔드는 문자열, 새 백엔드는 `{raw, diagnostics}`. **브리지가 두 형태를
  정규화**해 기존 파서에는 `raw` 만 전달하고, `diagnostics` 는 **같은 요청의 아카이브**에 넣는다.
- **금지** — 진단을 입력 `meta` 에 되써넣거나 모듈 전역의 '마지막 응답'으로 전달하지 않는다.
  요청이 겹칠 때 엉뚱한 요청에 귀속된다.
- **스키마** — task 별 스키마를 쓴다. 최상위 전부 optional 이면 `{}` 도 정상이라 주입할
  시드가 0개가 된다.

**스키마는 파서에서 전수 도출한다.** 계획서의 필드 표는 출처가 아니다 — 이미 누락이
확인됐다. `llm_learning.py:560` 은 `item['data_len']` 을 읽어 `data_len_override` 로
반영하는데 표에 없었다. `additionalProperties:false` 로 잠그면 이관과 동시에 길이 변이
기능이 조용히 사라진다. 착수 시 `_llm_make_seed` · `LearningMixin` · 시퀀스 파서 ·
`_llm_make_workload_desc` · `compile_recipe` 가 실제로 읽는 키를 대조한다.
`generators[].target_id` 도 대상이다.

`command` 는 enum 으로 못 박지 않는다 — 유효 명령이 제품·설정별로 동적이라 클라이언트가
알 수 없다. 구조화 출력이 보장하는 것은 **모양이지 의미가 아니다.**

**실패 처리** — 구조화 출력이 대신해 주지 않는다.

| 실패 | 확인 지점 |
|---|---|
| 출력 상한 도달로 잘림 | `finish_reason` |
| 서버가 스키마 거부 | HTTP 상태 + 오류 본문. 자유 형식 재시도는 **설정으로 켰을 때만** |
| 요청 실패·중단 | 타임아웃, 제한된 재시도 |
| 형식은 맞으나 쓸 수 없는 결과 | 기존 의미 검증 + **최종 채택 개수** |

클라이언트는 **임베딩부터 생성까지 요청 전체의 시간 예산**을 갖고, 예산 초과 후 도착한
결과는 폐기하며, 종료 시 진행 중 요청의 처리 정책을 명시한다.

**실패로 셀 것과 세지 않을 것** — '채택 0개'를 일괄 실패로 집계하면 정상 동작 중에 LLM 이
꺼진다.

| 결과 | 처리 |
|---|---|
| 통신 실패 · 잘린 응답 · 파싱 실패 · 잘못된 task 형식 | **실패 정책 적용** |
| 정상 응답이나 중복 등으로 신규 채택 0개 | 정상 처리, **기여 0** 으로 기록 |
| task 가 허용하는 빈 결과 | 정상 처리 |

**본체에서 함께 정리할 것**

- **낡은 안내 제거** — 실패 메시지가 `rag/srag_llm_service.py` 와 BRIDGE_DIR 을 지목한다.
  본체의 `_llm_bridge_dir()`(L1886) 를 포함한 브리지 전용 경로도 백엔드에 따라 갈라야 한다.
- **설정 전달** — 백엔드가 기본 `fuzzer_config.json` 을 따로 읽으면 `--config` 로 고른
  설정과 어긋난다. 실제로 로딩된 설정을 넘기는 경로가 필요하다.
- **실패 집계 분리** — `pc_sampling_fuzzer_v10.2.py:7542` 는 백엔드가 오류 없이 반환하면
  *파싱 성패와 무관하게* 연속 실패 수를 0 으로 되돌린다. 무효 응답이 반복되면 `fail_limit`
  에 영영 도달하지 않는다.

- **되돌리기**: `module_path` 등 설정 원복 → 사내 브리지로 복귀

### P2 — 로컬 RAG (2~3일)

**별도 검색 서비스를 띄우지 않는다** — 살았는지 감시할 프로세스를 다시 만들지 않는 것이
이 설계의 요점이다.

```
tools/rag_ingest.py
  JSONL  →  정규화·분할  →  bge-m3 임베딩(DGX /v1/embeddings)  →  rag/index/

rag/index/
  current            현재 버전을 가리키는 포인터 파일
  <version>/manifest.json    소스별 sha256 + 청크 범위 + 모델 revision/차원/정규화/분할 설정
  <version>/chunks.jsonl     doc_id / title / content / permission_groups
  <version>/vectors.f16.npy  임베딩 (float16)

rag/vllm_client.py
  질의 임베딩(HTTP)  →  numpy top-k  →  [참고 문서] 블록  →  chat completion
```

임베딩 상한 8,192 는 **질의와 문서 청크 양쪽**에 걸린다. **JSONL 레코드를 길이 제한이 있는
청크로 분할한다.** 임베딩 서버가 길이 초과를 반환하면 해당 청크를 더 분할해 제한된 횟수만
재시도한다. 처리하지 못한 청크를 **조용히 누락하거나, 전체 인덱스를 완성된 것으로 게시하지
않는다.** 이는 추출 품질과 별개다 — PDF→JSONL 이 잘됐다고 청크 길이까지 해결된 것은 아니다.

FAISS 는 필요 없다. 10만 청크 × 1024차원 float16 = 200 MB(벡터 원본만). numpy 는 이미
설치돼 있다. **"검색 수 밀리초"는 측정 전 가정이다** — 본문 텍스트·임시 배열·자료형 변환을
포함한 실제 메모리와 퍼징 중 검색 지연을 P2 검증에서 측정한다.

**증분 추가와 인덱스 갱신**

- **버전 디렉터리 + 포인터 파일** — 새 버전 디렉터리에 완성·검증한 뒤 **포인터 파일만**
  원자적으로 교체한다. 기존 디렉터리를 지우고 바꾸면 중간에 경로가 사라지는 순간이 생긴다.
- **실행 중 캠페인은 버전 고정** — 시작할 때 해석한 버전 경로를 유지하고, **사용 중인
  버전은 삭제하지 않는다.**
- **수정·삭제·중복 추가** — 같은 `doc_id` 재입력, 기존 문서 변경, 삭제를 manifest 에서 다룬다.
- **재현 정보 기록** — 임베딩 모델 revision·정규화 방식·차원·청크 분할 설정을 manifest 에
  남긴다. 모델이 바뀌면 인덱스를 못 쓴다는 것을 실행 시점에 감지해야 한다.

- **선행**: DGX 에 bge-m3 를 두 번째 vLLM 인스턴스로 기동. 사내에서 JSONL 추출·이관
- **되돌리기**: `retrieval.enabled=false` → P1 상태로 즉시 복귀

### P3 — 전환·측정 (캠페인 시간)

단계별 **깔때기 개수**를 남긴다 — HTTP 성공 → 정상 JSON → 의미 검증 통과 → 실제 시드 채택
→ 실행 → 신규 커버리지. 기여가 낮을 때 *어느 단계에서* 줄었는지 보인다. 학습 전략 개선이
아니라 **이관 검증에 필요한 계측**이다.

P1(검색 없음) ↔ P2(검색 있음) 비교는 제품·FW·시작 corpus·시간 예산·샘플링 조건을 맞춘
독립 실행들의 분포로 본다. 한 번의 실행에서 신규 코드 수가 많았다는 이유만으로 개선을
확정하지 않는다.

## 4. 결정 항목

리뷰 2회로 D1~D6 합의. D7 은 사다리로 확정했고 "이대로 간다" 확인만 남았다.

| | 항목 | 결정 | 조건 |
|---|---|---|---|
| **D1** | task/meta 전달 | 채택 | 최초·교정 호출에 동일 적용. `meta` 에 task·req_id·요청 context·**실제 적용 설정** |
| **D2** | HTTP 클라이언트 | `urllib` | 추가 pip 의존성 회피. 타임아웃·오류 본문 보존·**응답 크기 제한** 함께 |
| **D3** | generators 스키마 포함 | 포함 | 중첩 `anyOf` 문제 시 그 키만 제외. **스키마 미지원과 서버 장애를 구분**. 자유 형식 재시도는 **설정으로 켰을 때만** |
| **D4** | 단계 분리 | P1 → P2 | P1 자체가 LLM 경로를 되살린다 |
| **D5** | 생성 파라미터 | `max_tokens=16384`, `temperature=0.7` | 초기 실험값. task별 출력량·reasoning 사용량·잘림·지연 보고 조정 |
| **D6** | 기밀 정보 | 제약 없음 | 로컬 장비. `rag/index/` 는 저장소에 넣지 않는다. **아카이브에 무엇이 실제로 남는지 구현과 문서를 맞춘다** |
| **D7** | 검색 질의 생성 | 사다리 확정 | 아래 |

**D7 — 검색 질의**

1. 기본: `meta.rag_query` — 퍼저가 목표 함수명·명령 이름을 알고 있어 가장 정확
2. 호환 경로: 프롬프트 안의 기존 `[RAG-QUERY]` 블록
3. 둘 다 없음: 짧은 기본 질의, 또는 검색 생략
4. 서버가 토큰 초과 반환: 제한된 축소 재시도 후 **명시적 실패**

토크나이저 기반 절단은 **넣지 않는다.** 퍼징 PC 에 transformers·sentencepiece 를 다시
들이게 되는데, 예전 사내 환경에서 설치 문제로 걷어냈던 의존성이다. 문자·바이트 기준 제한을
쓰되 **정확한 토큰 수 보장이라고 표현하지 않는다.**

## 5. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 구조화 출력이 응답 품질을 떨어뜨림 | 디코딩 제약이 표현을 좁힘 | P1 에서 스키마 on/off 로 짧게 비교. 설정 스위치 유지 |
| DGX 지연이 exec/s 를 깎음 | LLM 워커가 블록되나 퍼징 루프는 계속 돎 | 기존 워커 구조가 흡수. 요청은 60초 주기 |
| bge-m3 재색인 필요 | 임베딩 모델을 바꾸면 인덱스를 다시 만들어야 함 | 사내와 같은 bge-m3 로 시작해 모델 고정. manifest 에 revision 기록 |
| 검색 품질이 사내 인덱스에 못 미침 | 근거 없는 제안이 늘어남 | P3 에서 측정. 못 미치면 P1 이 기준선으로 남아 있음 |
| DGX 가 단일 장애점 | LLM 경로 전체가 멈춤 | 기존 `fail_limit=10` 만으로는 부족(아래). 클라이언트 타임아웃·시간 예산으로 보완 |

### fail_limit 은 두 가지 경우를 못 잡는다

실패 횟수는 **호출이 반환된 다음에만** 올라간다. 요청 하나가 계속 걸려 있으면 10회에 영영
도달하지 않고, 퍼징 루프는 돌지만 LLM 경로는 멈춰 있다. 그리고
`pc_sampling_fuzzer_v10.2.py:7542` 는 백엔드가 오류 없이 반환하면 *파싱 성패와 무관하게*
연속 실패 수를 0 으로 되돌린다 — 무효 응답이 반복되는 경우도 못 잡는다.

### 되풀이하지 않을 것

이번 사고의 근인은 토큰 상한이었지만, 원인 추적을 막은 것은 **오류를 삼킨 코드**였다.
응답 본문에 `error_code` 가 담겨 있었는데 `result['hits']` 를 그대로 인덱싱해
`KeyError: 'hits'` 한 단어만 남았다. 새 클라이언트는 HTTP 상태와 오류 본문을 그대로 올린다.

## 6. 착수 전 통과 조건

| 항목 | 확인 내용 |
|---|---|
| 기존 응답 호환 | `data_len`, `generators`, setup 보존 필드를 포함한 v10.2 응답이 동일하게 처리되는지 |
| 실서버 구조화 출력 | 각 task 스키마, 중첩 `anyOf`, reasoning/content 분리, 출력 잘림, 빈 결과 — **실제 사용할 vLLM 버전·모델 조합**으로 |
| 백엔드 장애 | 무응답·연결 끊김·HTTP 오류·무효 JSON 에서 LLM 요청이 *끝나고* 퍼징이 계속되는지 |
| 인덱스 복구 | 추가 중 강제 종료, 같은 파일 재입력, 기존 문서 수정, 모델 변경 시 잘못된 인덱스를 쓰지 않는지 |
| Spark 동시 운용 | 생성·임베딩 서버를 함께 띄운 상태의 메모리·요청 지연·퍼저 exec/s 영향 |
| 회귀 및 복귀 | 장치 경로 AST 불변, `--config` 반영, 설정 원복 후 v10.2 백엔드 재사용 |
| 반환 계약 | 기존 문자열 반환과 새 `{raw, diagnostics}` 가 모두 처리되고, 진단이 **해당 요청에만** 기록되는지 |
| 의존성 없는 환경 | 토크나이저 패키지가 없는 환경에서도 검색이 동작하는지 |
| 청크 분할 실패 | 긴 JSONL 레코드의 분할 실패 시 **불완전한 인덱스가 게시되지 않는지** |
| 정상 0건 | 정상 응답의 중복·빈 결과로 실패 횟수가 오르거나 LLM 이 꺼지지 않는지 |

Nemotron-3-Super 의 Spark 용 1M 설정은 공식 배포 예제가 있으나 **특정 양자화·캐시·추론
파서 설정을 전제**한다. 같은 Spark 에서 bge-m3 서버까지 함께 돌릴 때의 메모리와 지연은
"Spark 동시 운용"에서 확인한다.

## 7. 범위 밖

- **Spec outcome 분모** — `V10_1_SPEC_OUTCOME_DENOMINATOR.md` 의 compiler/observe/guide 는
  별도 계획이며 이번 버전에 포함하지 않는다.
- **사내 RAG 스택 재현** — Elasticsearch 계열을 다시 세우지 않는다. 이 규모에선 과하다.
- **전체 스펙을 컨텍스트에 상주** — 공개 스펙 전체가 2M 토큰을 넘어 1M 에 들어가지 않는다.
  큐레이션한 부분집합을 고정 프리픽스로 넣는 방식은 P2 가 부족할 때 대안으로 남긴다.
- **장치 경로 변경** — 샘플러·NVMe 발송·커버리지 모델은 건드리지 않는다. AST 고정 시험으로 강제한다.
