# PPT 1장 구성안 — SSD 펌웨어 Coverage-Guided Fuzzer 개발 경과

> 대상: **고객 엔지니어**. 컨셉/연구 지향이 아니라 "이 도구가 무엇을 보장하는가" 를 설명하는 용도.
> 원칙: 내부 알고리즘 수식·코드·파라미터는 넣지 않는다. 축은 5개, 그림이 텍스트보다 넓게.

---

## 1. 슬라이드 제목 / 한 줄 메시지

**제목**
> 실기 기반 SSD 펌웨어 Coverage-Guided Fuzzer — 개발 경과 및 구성

**한 줄 메시지** (제목 바로 아래, 한 줄로)
> 펌웨어 재빌드·계측 없이 **양산 이미지 그대로** 실기에서 코드 커버리지를 관측하며 NVMe 펌웨어를 자동 퍼징하고, 발견한 불량은 **실행 가능한 재현 스크립트까지 자동 생성**한다.

이 문장이 슬라이드의 전부입니다. 나머지는 이 문장의 근거입니다.

## 2. 본문 5개 축 (슬라이드에 그대로 넣을 문구)

각 축은 **제목 1줄 + 근거 2줄 + 고객 가치 1줄**. 그 이상 쓰면 한 장에 안 들어갑니다.

### ① 비침습 커버리지 획득
- 디버그 포트(SWD/JTAG)로 **Program Counter 샘플링** — 펌웨어 수정·재빌드 불필요
- 두 방식 병행: 실행을 멈추지 않는 **PCSR** / 정밀 측정용 **J-Link halt**
- 정적 분석(Ghidra) 결합 → **Basic Block 단위**로 커버리지 환산
- → **양산 펌웨어를 그대로 테스트**. 계측 빌드를 따로 준비할 필요가 없음

### ② 스펙 인지 + 상태 인지 입력 생성
- NVMe 명령을 **CDW 필드 스키마 단위**로 변이 (필드 타입별 유효/예약/벤더 범위 구분)
- 단일 명령 → **명령 시퀀스** → **전원 상태(PS0~PS4)·PCIe 링크 상태** 조합까지 확장
- 장치 Telemetry 로 관측한 **상태**를 별도 코퍼스로 관리, 두 코퍼스 비중을 **자동 조정**
- → "명령 하나" 가 아니라 **명령 + 순서 + 전원/링크 상태** 의 조합 공간을 흔듦

### ③ 불량 포착과 자동 재현
- Timeout 발생 시 **코어 정지 PC 를 다중 샘플링** → hang 위치 특정
- J-Link 메모리 덤프 / 벤더 덤프 툴 **자동 실행**, dmesg·로그 동시 확보
- 직전 100개 명령을 **그대로 실행 가능한 replay 스크립트로 자동 생성** (전원·PCIe 조작 포함)
- → 재현 절차를 사람이 역추적할 필요 없음. 폴더 하나만 전달하면 재현

### ④ 무인 장기 운전 + 안전장치
- PMU 보드 **전원 사이클(POR)** 로 hang 자동 복구 → 사람 개입 없이 연속 운전
- 미지원 명령을 자동 판별·스킵 → 가성 불량으로 멈추지 않음
- **파괴적 명령 발송 차단 가드**: 전체 소거 / 잠금(Security) / 네임스페이스 파괴
- → **며칠 단위 무인 운전**, 장비·데이터 손실 없이 누적 커버리지 확보

### ⑤ LLM 결합 (최신 단계)
- 스펙 의미를 이해한 **시드·시퀀스 제안** — 랜덤 변이가 도달하기 어려운 조합 생성
- LLM 제안의 **실측 기여도(커버리지 획득량)를 근거로 가중치를 자동 조정** — 사람이 튜닝하지 않음
- → 랜덤 탐색과 지식 기반 탐색을 **자동 배분**

## 4. 수행 성과 (우측 하단, 3줄)

- 실기 **장기 무인 운전 확립** — 단일 세션 80만 명령 규모 누적 검증

## 5. 그림 제안 (우선순위 순)

### 그림 1 — 시스템 구성도 ★최우선, 슬라이드 좌측 절반
이 슬라이드에서 **가장 중요한 그림**입니다. 이것만 있어도 설명이 됩니다.
핵심은 **3개의 독립 채널**이 한눈에 보이는 것:

```
                    ┌─────────────────────────┐
      ┌────────────>│   SSD (DUT)             │
      │  ① 명령      │   ┌───────────────────┐ │
      │  NVMe        │   │ Controller        │ │
      │  passthru    │   │  Cortex-R5 코어   │ │
      │             │   └─────────▲─────────┘ │
┌─────┴──────┐      └─────────────┼───────────┘
│  Host PC   │  ② 관측            │ SWD/JTAG
│  (Fuzzer)  │<───────────────────┘
│            │      J-Link / OpenOCD  → PC 샘플링
│            │
│            │  ③ 전원   ┌──────────┐   전원 제어
│            │──────────>│ PMU 보드 │──────────────> SSD
└─────┬──────┘           └──────────┘
      │  ④ 링크 섭동 (setpci) ──────> PCIe Root Port
      │
      │  ⑤ 파일 브리지
      └──────────────────> [ LLM 서비스 PC ]
```

- **①번(명령)과 ②번(관측)이 분리돼 있다**는 점을 강조. 이게 "펌웨어 수정 없이 커버리지를 본다" 의 근거
- ③번은 "hang 이 나도 사람이 안 가도 된다" 의 근거
- 색: ① 파랑(입력) / ② 초록(관측) / ③ 빨강(복구) 로 구분하면 설명 없이 읽힘

### 그림 2 — 퍼징 루프 플로우 (그림 1 아래 또는 우측)
```
  [코퍼스] ──선택──> [변이] ──가드──> [발송] ──> [PC 샘플링]
      ▲                                              │
      │                                     새 커버리지?
      └──────────── 편입 ◀──── Yes ──────────────────┤
                                                     │ Timeout
                                                     ▼
                          [정지 PC 캡처] → [덤프] → [replay 생성] → [POR 복구] ─┐
                                                                              │
      ◀───────────────────────── 루프 복귀 ───────────────────────────────────┘
```
- 두 개 코퍼스(명령 커버리지 / 장치 상태)를 좌측에 나란히 두고 사이에 "비중 자동 조정" 화살표
- **Timeout 분기가 다시 루프로 돌아온다**는 점이 ④번 축(무인 운전)의 시각적 증거

### 그림 3 — 커버리지 성장 곡선 ★실데이터
- **이미 산출물이 있습니다**: `output/coverage_growth.png`
- 고객에게 "실제로 커버리지가 오른다" 를 보여주는 **유일한 정량 증거**. 반드시 실측 그래프로
- x축 실행 명령 수 / y축 누적 커버리지. 계단식 상승이 보이면 그것만으로 설득력 있음

### 그림 4 — 펌웨어 커버리지 맵 ★실데이터, 시각 임팩트
- **이미 산출물이 있습니다**: `output/firmware_map.png` 또는 `heatmap_1d.png`
- 펌웨어 주소 공간 중 어느 영역이 얼마나 실행됐는지. 색 밀도로 표현
- 고객 엔지니어가 자기 코드 영역을 찾아보게 되는 그림 — 대화가 열립니다

### 그림 5 — 개발 타임라인 바 (하단 전폭 스트립)
- 3월 ─ 4월 ─ 5월 ─ 6월 ─ 7월, 위에 v4~v9.6 마일스톤 점
- 각 점 위에 한 단어만: `시각화` `POR 복구` `상태 인지` `다중 제품` `LLM 결합`
- 높이는 슬라이드의 12% 이내로. 이건 보조 정보

### 그림 6 — replay 스크립트 스니펫 (여유 있으면, 작게)
- 자동 생성된 `.sh` 를 5~6줄만 잘라서 모노스페이스 박스로
- 메시지: "이 파일을 그대로 실행하면 재현됩니다"
- 신뢰감을 주는 데 효과가 큼. 단, 자리 없으면 과감히 뺄 것

## 7. 구두 설명 스크립트 (약 2분)

> "SSD 펌웨어를 실기에서 자동으로 흔드는 도구입니다. 일반 퍼저와 다른 점은 **펌웨어를 고치지 않는다**는 것입니다.
> 보통 커버리지를 보려면 계측 코드를 넣어 재빌드해야 하는데, 저희는 디버그 포트로 코어의 실행 위치를 샘플링해서
> 커버리지를 얻습니다. 그래서 **양산에 올라가는 이미지 그대로** 테스트합니다. (그림 1의 ①② 지시)
>
> 흔드는 대상은 NVMe 명령인데, 필드 단위 스펙을 알고 흔듭니다. 그리고 명령 하나가 아니라 **명령 순서와
> 전원·링크 상태 조합**까지 같이 흔듭니다. 실제 불량은 대개 단일 명령이 아니라 이런 조합에서 나오기 때문입니다.
>
> 불량이 나면 코어가 어디서 멈췄는지 PC 를 잡고, 메모리 덤프를 뜨고, **직전 명령 100개를 실행 가능한
> 스크립트로 자동 생성**합니다. 폴더 하나 전달하면 그쪽에서 바로 재현됩니다. (그림 6 지시)
>
> 그리고 hang 이 나면 PMU 로 전원을 다시 넣어 스스로 복구합니다. 그래서 사람 없이 며칠 돌립니다.
> 대신 드라이브를 망가뜨릴 수 있는 명령 — 전체 소거, 잠금, 네임스페이스 삭제 — 은 발송 단계에서 막습니다.
>
> 이 그래프가 실제 측정치입니다. (그림 3 지시) 3월부터 5개월간 이 단계까지 왔고, 최근에는 LLM 이
> 스펙을 이해한 시드를 제안하게 하고 **그 기여도를 실측해서 비중을 자동으로 조정**하도록 만들었습니다."

## 8. 넣지 말 것

고객 엔지니어 대상에서는 **역효과**입니다:

- 알고리즘 수식 (에너지 스케줄 공식, 코퍼스 선택 확률 갱신식)
- 내부 파라미터·설정 키 이름
- 버전별 상세 변경 이력 (v9.4가 v9.3과 어떻게 다른지)
- 코드 스니펫 (replay 스크립트 예외 — 그건 산출물이라 의미가 다름)
- 미확정 결함을 확정처럼 쓰는 표현

질문이 들어오면 답하면 됩니다. 슬라이드에 미리 넣을 필요는 없습니다.
